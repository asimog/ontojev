# API-first GDC strategy

Authority: supplied `API_UG.pdf`, 288 pages, especially sections 1.2 and 1.4. References below are PDF page numbers, not assertions from the old repositories. All behavior not confirmed there is **UNVERIFIED**. Documentation confirmation is not a successful live integration test. No live GDC call was made in Phase 0.

Before any file acquisition, evaluate these in order: (1) analysis endpoint, (2) metadata/search, (3) bounded expression endpoint, (4) bounded SSM/CNV occurrences, (5) another small targeted query. **This design proposes no GDC file acquisition.** If all appropriate options are inadequate and a large file would be needed, the answer is `UNSUPPORTED_IN_V1`.

## Endpoint mapping

| Endpoint | Confirmed contract in supplied guide | CancerJEV use and limits |
|---|---|---|
| `/projects` | Project inventory, program relationships; `from`, `size`, sorting (pp. 8–10; parameters pp. 28–55) | Discover project IDs and program context; paginate metadata separately from the <=12 investigated projects. Inventory is not a scientific scan of every project. |
| `/cases` | Case and nested metadata, field selection, filters and pagination (section 1.2.1; pp. 19 onward) | Bounded population manifests, clinical/sample metadata and availability; never call every case biologically comparable. |
| `/files` | File metadata/search, including access and workflow fields (section 1.2) | Optional bounded provenance/availability lookup only, with `files.access=open` AND caller filter; no `/data` call follows. Open metadata about a controlled file does not authorize acquiring it. |
| `/genes` and `/{gene_id}` | Gene identifiers, symbols, biotype, coordinates (p. 68) | Resolve a bounded gene roster; coordinates alone do not imply compatible assays. |
| `/analysis/top_mutated_genes_by_project` | Filter example `case.project.project_id`, impact filter, `fields=gene_id,symbol`, paginated hits with `_score` (pp. 106–108) | Mutation fast-search lane, <=100 returned hits/project/lane. `_score` is a provider ranking calculation, explicitly not mutation count, p-value or significance. |
| `/analysis/top_cases_counts_by_genes` | `gene_ids`; per-project gene mutation case counts under nested aggregations; cannot use `fields` or `format` (pp. 95–105) | Cross-project count context. Multi-gene wire encoding, project restriction, and pagination of aggregation buckets are **UNVERIFIED** from examples inspected. Do not ship an unrestricted all-project call as a 12-project scan. Disable until a bounded contract is confirmed; fallback to targeted occurrences. |
| `/analysis/top_mutated_cases_by_gene` | Case results for selected genes/project, `fields`, filters and bounded `size` (pp. 109–111) | Optional case-dominance screening; top-ranked cases do not describe an unbiased case population. Exact scientific meaning of `_score` is **UNVERIFIED**; retain only as ranking metadata. |
| `/analysis/mutated_cases_count_by_project` | `size=0` aggregation; affected count at `projects.buckets[].case_summary.case_with_ssm.doc_count` (pp. 112–114) | SSM-data population context, never universal assay-callability or matched-gene denominator. Project/filter semantics and complete-bucket retrieval are **UNVERIFIED**; disabled for scoped science until confirmed. `size=0` does not mean an empty response. |
| `/gene_expression/availability` | POST `case_ids`, `gene_ids`; JSON per-case/per-gene booleans and counts; protein-coding genes (p. 69) | Check <=250 cases and <=100 explicit genes. Availability is not a guarantee of assay/sample matching. |
| `/gene_expression/gene_selection` | POST case IDs; exactly one of `gene_ids` or `gene_type=protein_coding`; `selection_size`; optional `min_median_log2_uqfpkm` default 1; returns gene ID/symbol, log2-UQFPKM SD and median (pp. 70–71) | Expression wide lane; deterministic <=250-case collection; selection_size<=100. Server-side protein-coding universe is allowed: it sends no explicit >100-ID list. Record this universe and the expression threshold. |
| `/gene_expression/values` | POST case/gene IDs; TSV only; `tsv_units` exactly `uqfpkm` or `median_centered_log2_uqfpkm` (pp. 69–70) | Focused deep data. Request UQFPKM, join by actual case/gene column labels, validate missing columns and units. Compute log2(x+1) and any centering after assembling the intended population. Never concatenate independently centered batches as a single cohort. |
| `/ssms` / `/{id}` | Variant records; filters, consequence/observation expansions (pp. 66–67,72–73) | Focused variant annotation and explicitly needed read support; no unrestricted expansion. |
| `/ssm_occurrences` / `/{id}` | Variant occurrence in a case; `case.submitter_id` example, fields/TSV, diagnostic expansion (pp. 74–75) | Unique case/gene membership within observed source semantics, not a count of occurrence rows. Exact field manifest for combined gene/project/sample restrictions must be confirmed; otherwise **UNVERIFIED** and lane disabled. |
| `/cnvs` / `/{id}` | Gene-level CNV category/coordinate records; `cnv_change`, `cnv_change_5_category`, `gene_level_cn`; consequence.gene (pp. 76–78) | Categorical gain/loss and amplification/deletion evidence. Does not establish a continuous absolute copy-number measure. |
| `/cnv_occurrences` / `/{id}` | CNV applied to cases; combined availability filters and expanded case/CNV (pp. 79–81) | Focused categorical CNV membership. Preserve multiple observations and resolve ambiguous mappings explicitly. Absence is not automatically diploid. |
| `/segment_cnvs`, `/segment_cnv_occurrences` | Detail lookup and POST search/filter examples (pp. 82–89) | Future registered targeted context only. The guide's example described as overlap uses start>=lower and end<=upper (containment); do not adopt it as a correct general overlap predicate. General overlap query semantics remain **UNVERIFIED** until tested. |
| `/analysis/survival` | Filters are an array of groups; project, mutation and explicit case-barcode group examples; donors with time/censored/survivalEstimate; comparison overallStats chiSquared/pValue; fields/format not adjustable (pp. 115–121) | Targeted grouped survival exploration. No promised Cox model, hazard ratio, confidence intervals, covariate adjustment, pagination, or exact log-rank implementation: **UNVERIFIED**. |

Search filters use `{op,content:{field,value}}` and compound `{op:"and",content:[...]}`. `exclude` differs from `excludeifany` for multivalued properties (pp. 29–34). Endpoint-specific field prefixes differ (`case`, `cases`, `gene`, `genes`); do not reuse a global field translation blindly. Standard search pagination uses `from` offset, `size`, and `data.pagination`; aggregations need their own parser and completion rules. Missing pagination is not proof of completion.

Preserve `timed_out`, shard failures, aggregation error bounds and `sum_other_doc_count`. A nonzero error/truncation makes totals partial. Do not substitute absent buckets with observed zeros.

## Inventory, traversal and broad discovery

Refresh small inventory responses at a 24-hour TTL. Freeze the discovered project roster/hash for a sweep; sort project IDs; process the next <=12. New projects join the next sweep. Record attempted/skipped/incomplete dispositions. Deferred projects re-enter by fair rotation; promising Jev results do not monopolize traversal. Case/gene offsets prevent every sweep inspecting only the first identifiers.

Inventory may itself need >10 pages: persist an incomplete inventory cursor and continue a later run rather than opening a new logical query to evade the page cap. Global metadata enumeration is distinct from scientific project admission, and every request still consumes the owning run's byte/request budget.

For a first live slice use mutation ranking and expression variability lanes. CNV is focused supporting evidence until a cheap broad lane is demonstrated. Each lane returns <=100 hits per project. Each selected case collection is deterministic (sorted stable IDs and persisted offset), with observed universe hash, eligible_n when known, selected_n and completeness. If a bounded case listing is partial, label it a sample of the enumerated frame, not the whole project.

Validity prefilter rejects unusable/malformed/provenance-free states; it does not threshold p/q or demand a large effect. Diversity downselection assigns states to deterministic primary strata `(project, lane, modality, anomaly_shape, direction)` from deterministic features; stable hash order within strata, round-robin across strata, duplicate entity/context removal, stop at 1,000. Record every selection/defer reason and seed/version. No model judgment is needed before this cap.

Top-k endpoint discovery remains selection-biased even after a permissive local filter. Preserve this limitation; add a small stable rotating gene lane through bounded gene metadata only when budget permits. Do not claim the first two lanes explore all possible biological signals.

## Scientific limits of the API-first approach

- `case_with_ssm` is source availability context, not proof of whole-genome callable negatives. Matched recurrence denominators require consistent source/filter semantics; absent denominator means count-only evidence.
- Expression response examples omit an unavailable requested case. Use returned labels and an explicit missingness manifest; never align by request order.
- Case-level expression may hide sample selection/aggregation. Exact sample resolution, workflow selection and tie-breaking are **UNVERIFIED** in the supplied sections. Refuse sample-matched cross-modal claims until provenance supports them.
- Categorical CNV cannot be passed to the old continuous Pearson-correlation method without a newly defined valid estimator. Start with categorical comparisons where supported; otherwise defer.
- Survival group request IDs count across all groups together (<=250 total supplied IDs). Server survival curves or p-values from separate batches cannot be averaged. For larger groups retrieve bounded individual clinical records and use a separately registered local method if complete, otherwise defer. Negative donor times shown in the guide require an explicit eligibility policy, never silent clamping.
- GDC release atomicity across requests and historical replay by an API snapshot token are **UNVERIFIED**. Preserve raw responses/hashes and retrieval times; record known release markers or null. Reproducibility means replay from retained inputs, not an assertion that a future API request is identical.

First real follow-up should be `STRATIFY_BY_PROJECT_V1`, using already-held deterministic observations; it can genuinely test whether recurrence is dominated by one project without extra acquisition. Add expression-by-mutation or survival only after eligibility and mapping contracts pass. The registry is not a commitment to implement all nine proposed methods.
